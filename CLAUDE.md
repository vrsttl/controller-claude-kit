# CLAUDE.md

Maintainer notes for `controller-claude-kit`. This file is for the developer working on the kit on this Mac. It is not shipped to the end user (her user-level file is `home/CLAUDE.md`, written in Hungarian).

## Purpose

This repo builds a packaged, one-script-installable Claude Code setup for a Hungarian finance controller on a Windows 11 laptop. The kit gives her a self-serve loop from ad-hoc question to repeatable monthly Excel and Power BI reports fed by szamlazz.hu invoice data, onboards her progressively into Claude Code features across three levels, and ships hooks, rules, agents, skills and a per-project `/prime` bootstrap. Everything under `home/` is copied into `%USERPROFILE%\.claude\` by `install.ps1`; everything under `templates/project/` scaffolds her `%USERPROFILE%\Riportok` working folder. The full design contract lives in `docs/PLAN.md`.

## Verify

Run these from the repo root before every commit:

```bash

```

Individually:

```bash
uv run pytest -q
uv run ruff check scripts home/hooks
pwsh -NoProfile -File tests/test_settings_merge.ps1
```

`pyproject.toml` at the repo root exists only for dev tooling on this Mac. The shipped scripts under `scripts/` are self-contained PEP 723 files and do not read it.

## Conventions

- Hungarian for every string she reads: `home/CLAUDE.md`, `README.md`, rules, interview prompts, Excel sheet names and labels, hook messages, validation errors.
- English for everything a machine reads: code, file names, agent and skill names, spec.yaml keys, Excel Table names, column headers, git commit messages.
- No em dashes anywhere. Use commas, periods, colons or parentheses. The one exception is `docs/PLAN.md`, which is a verbatim copy of the agreed plan.
- Hooks are Python standard library only, no third-party imports, and fail open: any unexpected error must let the tool call through and log to `~/.claude/hooks/.hook-errors.log`.
- Scripts carry PEP 723 inline metadata headers and are executed with `uv run`. Never assume a shared virtualenv on her laptop.
- `settings.json` is merged, never overwritten. Kit hook entries carry `"kit": "controller"` so the merge can replace only its own entries.
- Delivered `.xlsx` files are never written directly. Build into `.staging/` and move.

## Contract

`docs/PLAN.md` is the shared contract. Every phase agent reads it before writing anything. If an implementation detail contradicts the plan, the plan wins unless the plan is amended first.
